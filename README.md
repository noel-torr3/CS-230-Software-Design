# CS 230 Software Design

## The Gaming Room Portfolio Reflection

### The Gaming Room and Software Requirements

For this project, I worked with a client called The Gaming Room. They had a game called Draw It or Lose It that was originally developed for Android, and they wanted to expand it into a web-based application that could work on different devices and operating systems. The application needed to manage games, teams, and players while making sure names were unique and the game information stayed organized. It also needed to be reliable and secure while supporting multiple users.

### What I Did Well

I think one thing I did well was explaining the different parts of the system and how they work together. The UML diagram helped me show the relationship between GameService, Game, Team, Player, and Entity. I also explained how things like inheritance, encapsulation, and the Singleton pattern were being used instead of just showing the diagram without explaining it.

### How the Design Document Helped

Working through the design document was helpful because it made me think about how the application should work before focusing only on the code. Looking at the requirements, constraints, operating systems, storage, memory, and security made it easier to understand why certain design choices were being made. It gave me a better idea of what the finished application would need instead of just writing code and figuring everything out afterward.

### What I Would Revise

If I could revise one part of the document, I would probably improve the evaluation section. There was a lot of information to compare between Mac, Linux, Windows, and mobile devices, and I think I could make some of the comparisons more detailed and easier to read. I would also make sure the advantages and disadvantages are directly connected to what The Gaming Room actually needs.
